# PurrPurrTown demo — 运行与测试说明

> 依据《开发整理第一阶段》《游戏开发SOP》《交互规则.xlsx》补齐基础玩法后整理。
> 核心闭环已跑通：**捡瓶子 → 背包 → 找乌乌 → 对话点「交易」→ 卖瓶子 → 金币增加**。

## 二、怎么跑

**方式 1：编辑器里跑**
1. 打开 Godot，导入 `E:\game\PurrPurrTown\demo\project.godot`
2. 按 `F5` 运行（主场景 `tscn/main.tscn`）

**方式 2：命令行直接跑**
```powershell
& 'E:\SteamLibrary\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe' --path 'E:\game\PurrPurrTown\demo'
```

## 三、操作键位

| 操作 | 键位 |
|---|---|
| 移动 | `W` `A` `S` `D`（或方向键） |
| 跑步 | 按住 `Shift` |
| 拾取 | 鼠标左键**点中物品**（要在拾取范围内） |
| 打开/关闭背包 | `B` |
| 和 NPC 对话 | 走到 NPC 附近按 `E`（再按一次关闭） |
| 关闭对话框 | `×` 按钮 或 `Esc` |
| 关闭交易界面 | `×` 按钮 或 `Esc` |
| 镜头缩放 | 鼠标滚轮（0.5×～3.0×） |

## 四、交易操作规则（对应《交互规则.xlsx》）

| 玩家操作 | 行为 |
|---|---|
| 点击背包物品 | 移 1 个到交易栏 |
| **长按 0.5 秒** | 移 10 个（不足 10 个就全移） |
| 一键售出 | 背包里所有**该 NPC 收的分类**全部移到交易栏 |
| 确定售出 | 结算交易栏：扣背包、加金币、清空交易栏 |
| 点击交易栏某一行 | 拿回 1 个（点错了可以反悔） |

交易界面右侧**只显示该 NPC 收货分类**的物品：乌鸦老板（乌乌）只收「废品」，白菜这类「农产品」不会出现在他的交易界面里。

## 五、数据在哪改

全部集中在 `script/GameData.gd` 的四张表：

| 表 | 作用 |
|---|---|
| `ITEM_NAME` | 物品 ID → 中文名 |
| `ITEM_CATEGORY` | 物品 ID → 分类（废品 / 农产品…） |
| `PRICE_TABLE` | 物品 ID → 收购单价 |
| `NPC_TRADE_CATEGORY` | NPC id → 收哪些分类（不在表里的 NPC 只闲聊不交易） |

新增一个能交易的 NPC：场景里给它挂 `script/area_2d.gd`，在检查器填 `npc_id`，然后在上面的 `NPC_TRADE_CATEGORY` 里登记这个 id 即可，**不用改代码**。

## 六、测试

**一键跑全部**
```powershell
cd 'E:\game\PurrPurrTown\demo'
.\tests\run_all.cmd
```
> 用 `.cmd` 而不是 `.ps1`：这台机器的 PowerShell 执行策略禁止直接运行脚本文件，
> `.cmd` 里已经带上 `-ExecutionPolicy Bypass`，双击也能跑。

**单独跑某一项**
```powershell
$g = 'E:\SteamLibrary\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe'

# 交易逻辑单元测试（32 条断言：数据表、背包增删、容量上限、分类过滤、长按数量、结算）
& $g --headless --path . res://tests/test_trade.tscn

# 端到端流程测试（28 条断言：点击拾取命中 → 按 E 对话 → 点交易 → 卖东西 → 金币 → 界面锁移动）
& $g --headless --path . res://tests/test_flow.tscn

# 主场景冒烟（跑 90 帧，看有没有脚本/节点错误）
& $g --headless --path . --quit-after 90
```

退出码 `0` 表示全过，非 `0` 表示有失败，可直接接进 CI。

**重新生成界面截图**（会输出到 `_shots/`，需要带窗口，不能 headless）
```powershell
& 'E:\SteamLibrary\steamapps\common\Godot Engine\godot.windows.opt.tools.64.exe' --path . --resolution 1280x720 res://tests/capture_ui.tscn
```

## 七、这次改了什么

### 修掉的硬伤
- `area_2d.gd` 里 `preload("res://DialogUI.tscn")` 路径不存在（文件在 `tscn/` 下），**整个脚本编译失败**，已修正。
- `main.tscn` 里 `BagUI/GoldUI/Pickup_Berry` 三个引用写的是 `res://Xxx.tscn`，实际文件在 `tscn/` 下，靠 uid 侥幸能加载，已改成正确路径。
- `pickup.gd` 一次点击捡光范围内所有瓶子的 bug：改为判断鼠标是否真的点中自己，并 `set_input_as_handled()` 阻止其他拾取物抢同一次点击。
- `GameData.gold` 的信号回调里不再写 `gold +=`，`gold_ui.gd` 里「每 1 秒自动加 1 金币」的测试循环已删除（原 SOP 的 P2 项）。
- 玩家识别从 `body.name == "CharacterBody2D"` 改成 `player` 组，节点改名不再连坐。

### 新增
| 文件 | 作用 |
|---|---|
| `script/trade_ui.gd` + `tscn/TradeUI.tscn` | 交易界面：分类过滤、点击/长按/一键售出、结算 |
| `script/dialog_ui.gd` | 对话表现层，带 `chat_pressed` / `trade_pressed` / `closed` 信号 |
| `tests/test_trade.gd` / `.tscn` | 交易逻辑单元测试 |
| `tests/test_flow.gd` / `.tscn` | 端到端流程测试 |
| `tests/capture_ui.gd` / `.tscn` | 界面截图工具 |
| `tests/run_all.cmd` + `run_all.ps1` | 一键测试（`.cmd` 是入口，绕过本机执行策略） |

### 重写/调整
- `script/GameData.gd`：加物品表、分类表、价格表、NPC 收货表；`add_item() -> bool` 带背包满判断；`inventory_changed` 信号；`UiState` 状态枚举。
- `script/bag_ui.gd`：格子改为运行时统一生成（原来场景里手搓 60 个，其中还误在 slot48 里塞了 12 个），带容量显示「背包 N/60」。
- `script/character_body_2d.gd`：加入 `player` 组；对话/交易时锁移动。
- `tscn/DialogUI.tscn`：补「闲聊」「我要卖点东西」按钮、修正立绘/姓名框/对话框背景的尺寸（原来 scale 是 1e-05，等于看不见）。
